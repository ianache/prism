# Rust S12 TLS E2E Stabilization Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Complete process-level TLS verification for `prism-run` while preserving JSONL, authentication, bounded concurrency, lifecycle, and the 100,000-frame target.

**Architecture:** Retain the S11 Rustls server and separate handshake timeout from worker read timeout. Use test-only certificate material and a stable client harness to exercise the real process; keep plaintext tests as unchanged regressions.

**Tech Stack:** Rust stable, Rustls 0.23, rustls-pemfile 2, Python 3, PowerShell, Cargo workspace.

**Spec:** `docs/superpowers/specs/2026-09-13-rust-s12-tls-e2e-design.md`

## Global Constraints

- Preserve the 100,000-frame benchmark target and S7–S11 contracts.
- No plaintext fallback when TLS is configured.
- Never commit or log private keys, certificates, or tokens.
- No mTLS, rotation, broker, persistence, remote deployment, or P0 claim.

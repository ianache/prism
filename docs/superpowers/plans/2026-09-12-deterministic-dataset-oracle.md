# Deterministic Dataset Generator and Correctness Oracle Implementation Plan

> For agentic workers: REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax.

**Goal:** Implement the reproducible Python generator, oracle, and verifier that produce and validate the frozen PRISM P0 telemetry dataset.

**Architecture:** Use a Python 3 standard-library package under tools/dataset. Keep PRNG, frame codec, rule evaluation, oracle, generation, and verification in separate modules with typed dataclasses at their boundaries. The oracle independently executes F1-F6 over bytes and emits canonical JSONL; generated bytes are written to a temporary directory and promoted only after verification.

**Tech Stack:** Python 3 standard library, dataclasses, argparse, hashlib, json, pathlib, tempfile, unittest, and no third-party dependencies.

**Spec:** docs/superpowers/specs/2026-09-12-deterministic-dataset-oracle-design.md; specification/telemetry-workflow.md; specification/rule-table.json; contracts/data/*.schema.json; datasets/*.json.

## Global Constraints

- Use seed 0x505249534D5F5631 and SplitMix64 with uint64 wraparound.
- Use only integer/fixed-point arithmetic; no floating point in canonical generation or oracle logic.
- Use CRC-32C Castagnoli with reflected polynomial 0x82F63B78, init/xorout 0xFFFFFFFF.
- Validate F1 in the fixed order: truncation, magic, version, length, protocol, ranges, checksum.
- Generate payload classes 105, 249, and 501 bytes with exact workload counts for count=1,000,000.
- Preserve lexicographic fixture order, canonical UTF-8 LF JSONL, SHA-256 digests, and immutable raw inputs.
- Do not implement B0/B1 runtimes, performance measurement, transport, or production workflow behavior.
- All commands must work from the repository root with python -m and no network access.
